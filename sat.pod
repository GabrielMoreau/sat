=head1 NAME

sat - schedule a one-shot command using systemd timers


=head1 SYNOPSIS

 echo "bash command" | sat DATE TIME


=head1 DESCRIPTION

SAT was designed as a lightweight system administration tool providing an B<at>-like interface with systemd persistence.

B<sat> is a simple replacement for B<at> designed for Linux systems using systemd with persistence (reboot).
It schedules a command or shell script for a single execution at a specified date and time.
Unlike traditional B<at>, scheduled jobs are stored as persistent systemd timers and survive system reboots.
The command is read from standard input and stored as an executable shell script.
The command is then executed once by systemd.
After successful execution, the job is automatically removed.
If the command exits with a non-zero status, the job is kept for inspection and manual action.
Failed jobs are disabled and are not automatically retried.


=head1 DATE AND TIME FORMAT

The date and time argument accepts GNU date-compatible expressions.

Examples:

 sat now +5min

Schedule a command five minutes from now.

 sat today 18:00

Schedule a command today at 18:00.

 sat tomorrow 09:30

Schedule a command tomorrow at 09:30.

 sat 2026-08-31 23:59

Schedule a command at an absolute date and time.

The specified date must be in the future.
Dates and times are converted internally to an absolute timestamp before creating the systemd timer unit.

Seconds may be specified when required:

 sat 2026-08-31 23:59:30


=head1 SHELL EXECUTION

By default, jobs are executed using B</bin/sh>.
The shell can be selected with command line options:

=over 4

=item B<-b>, B<--bash> Execute the job using B</bin/bash>.

=item B<-z>, B<--zsh> Execute the job using B</bin/zsh>.

=back

The selected shell must exist and be executable on the system.
The command received from standard input is stored as a shell script with the following structure:

 #!/bin/sh
 set -e

 command

The shell option only affects execution of the generated job script.
It does not change the shell used to invoke B<sat> itself.


=head1 EXAMPLES

Schedule a command:

 echo "usermgmt to-staff --employer DoD --job Programmer johndoe" | sat 2026-08-31 23:59

Example output:

 scheduled job 000042 at 2026-08-31 23:59:00

List scheduled jobs:

 satq

Remove a scheduled job:

 satrm 42


=head1 USER MODE

When executed as a regular user, B<sat> uses the user's systemd instance (B<systemctl --user>) instead of the system-wide instance.
To allow scheduled jobs to run after the user has logged out, lingering must be enabled:

 loginctl enable-linger USER

Without lingering, user timers are active only while the user's systemd session is running.


=head1 STORAGE

Jobs are stored below:

 (root) /var/lib/sat/job/
 (user) ~/.local/state/sat/job/

Each job is stored as an executable Bash shell script:

 (root) /var/lib/sat/job/000042.sh
 (user) ~/.local/state/sat/job/000042.sh


Generated systemd timer units are stored below:

 (root) /etc/systemd/system/
 (user) ~/.config/systemd/user/

with names:

 sat-000042.timer


=head1 EXECUTION MODEL

Each job is executed through the systemd template service:

 sat-run@.service


The service runs:

 /usr/libexec/sat/sat-run JOB_ID


Systemd provides:

=over 4

=item * persistence across system reboots;

=item * execution tracking;

=item * journal logging;

=item * integration with standard system administration tools.

=back


=head1 JOB LIFECYCLE

A scheduled job follows this lifecycle:

 waiting -> running +-> removed
                    |
                    +-> failed

Successful jobs are automatically removed.
Failed jobs remain available for inspection and manual removal.


=head1 FAILURE HANDLING

If a job exits successfully:

=over 4

=item * the timer is disabled;

=item * the timer unit is removed;

=item * the job script is removed.

=back

If a job exits with an error:

=over 4

=item * the timer is disabled;

=item * the job script is kept;

=item * the failure state is recorded;

=item * no automatic retry is performed.

=back

The administrator must decide whether to inspect, remove, or manually run the failed job.
